# 卡名命名规则

> 默认从**卡面（照片）**取名，更可控、不卡环节；只有当用户选择「逐张定制卡背」且背图有明显主题时，才用卡背主题润色。

## 默认流程（绝大多数情况）

1. 先用脚本生成的 `crop_preview.png`（卡面裁切预览总览）或逐张 Read 看 `cardNN` 图像。
2. **批量看所有卡面后**，再逐张起名——不要边抽边临时起名。
3. 一张卡面对应一个卡名；所有名称**去重**。

## 命名规范

- **默认四个汉字**（如「樱桃物语」「花朝初见」），贴合画面气质，不泛泛。
- **风格可配**：四字可爱 / 四字诗意 / 二字萌系 / 用户自定义。由 Phase 1 确认，写进 `config.json` 的 `namingStyle`。
- 卡名**不要自动附加编号**（如「晚风秘密 · 22」会破坏美感）。序号由系统用 `id` 管理，不进名字。

## 例子

- 卡面是樱桃卷蛋糕场景 → 产出「樱桃物语」，而不是「甜点 05」。
- 卡面是星空剪影 → 产出「星河信笺」。
- 用户指定「二字萌系」→ 产出「樱樱」「星崽」。

## 何时从卡背润色？

仅当用户 Phase 1 选了「逐张定制卡背」且已提供/设计出对应卡背时：

1. 先看卡面，从卡面取基础名；
2. 再看对应卡背，若背图主题鲜明，可把背元素融进名字（如卡面是女孩、背图是月亮，可润为「月见少女」）。
3. 最终名字仍需用户确认。

若用户选「统一卡背」或「分组卡背」，卡背没有逐张信息，**必须从卡面取名**。

## 重命名（必须给用户示例）

每次列出卡名清单时，末尾必须附一句：

> 这些名字都能改。直接发「把【旧名】改名成【新名】」就行，例如「把樱花物语改名成樱桃物语」，我马上改并重跑。

也支持批量覆盖表，写在 `config.json` 的 `override` 里：

```json
{ "override": { "樱桃物语": "莓好时光", "星河信笺": "星夜邮差" } }
```

## 兜底

若暂未命名，脚本用占位名「未命名 NN」（NN 为序号），站点仍可运行；上线前务必替换成真正卡名。
