# 工程规则（从实战项目 + GPT 复盘沉淀）

> 这些是本 skill 默认就遵守的工程质量门槛，避免「抽到了图鉴空白」「卡背卡面配错」「翻牌仍是镜像卡背」等问题。

## 1. 先建立完整卡牌目录，不边抽边生成
每张卡一开始就有固定数据：`id / name / rarity / frontImage / backImage`。图鉴、动画、记录、详情页全部读这一份。避免临时生成导致的数据错位。

## 2. 全站只用一份用户存档（UserGameState）
存档至少含：积分、卡牌库存与持有数量、首次/最近获得时间、抽卡记录、保底计数、未确认抽卡结果、已兑换口令。各页不各自维护状态；抽卡确认时统一写入并持久化（localStorage）。

## 3. 抽卡结果与动画分离
- 先生成抽卡结果（决定稀有度+具体卡）；
- 动画只负责展示；
- 用户点「收下全部」才调用唯一结算函数，同步更新库存/图鉴/记录/保底/积分；
- **未确认结果必须持久化**，刷新不丢。

## 4. 十连区分「新卡」与「重复卡」
- 本次第一次获得的新卡：逐张展示卡背→卡面（保留仪式感）；
- 已拥有或本次重复的卡：直接以卡面缩略图并列展示；
- 新卡揭完再显示本次全部结果，一次点击收下。

## 5. 图鉴默认用「灰色卡背」，不是灰色卡面
未解锁显示**对应卡背 + 强灰化/暗化 + 不可点详情**；已解锁显示彩色卡面 + 数量角标；详情页卡面与卡背并列；重复卡数量递增（×3）。

## 6. 翻卡用「切换 src」，不用脆弱的双面 3D 叠层
以「当前揭晓状态」切换 `src` 为卡背或卡面；用 CSS 旋转/缩放/闪光模拟翻转；**不依赖 `backface-visibility` 双面渲染**（曾出现翻开仍是镜像卡背的兼容问题）。

## 7. 兑换码功能的边界（必须说清）
前端版兑换码写在 `config.js` 里，**同一浏览器只能用一次**（靠 localStorage 记录已兑换口令）。需明确提示用户：
- 换浏览器 / 清数据后仍可再次兑换；
- 不要把它宣传成「全网唯一一次性密钥」。
- 若要做到「一个口令全网只一人可用」，需要服务器 + 数据库，超出本 skill 纯前端范围。

## 8. 素材质量门禁（build 自动做）
`scripts/build_site.py` 自动检查并报告：
- 卡面/卡背数量一致、按序号配对（card01 ↔ back01）；
- 卡名去重、数量一致；
- 稀有度仅存在于设定的档位；
- 生成卡背总览图便于统一命名；
- 至少手动验证：单抽、十连、重复卡、图鉴、刷新恢复、口令重复兑换。

## 9. 可配置项（不要写死）
| 配置 | 本 skill 默认（最终版） |
|---|---|
| 卡牌数量 | 按素材自动识别 |
| 稀有度 | R / SR / SSR / 隐藏款 |
| 初始积分 | 300 |
| 单抽 / 十连 | 10 / 90 |
| 保底 | 50 抽 SSR 或更高 |
| 兑换码 | 10 个普通码(500) + 1 万分码(10000) |
| 存档 | 浏览器 localStorage |
| 命名风格 | 四字、依卡背、不可重名 |
| 新卡动效 | 逐张揭晓 |
| 重复卡动效 | 直接并列卡面 |
